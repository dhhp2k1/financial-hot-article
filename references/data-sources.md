# 数据源与工具 v7.3

核心是 `scripts/mkt.py`：一个文件，核心功能零依赖（只用 Python 标准库），每类数据至少两个源，输出自带来源和抓取时间。写稿时先跑脚本拿数，再去搜索拿消息面，二者分开。

## 0. 安装与自检

依赖装在 skill 文件夹自带的 `.venv` 里，不碰系统 Python：

1. 双击 skill 根目录的 `setup.bat`（会建 `.venv`、装 `requirements.txt`、跑自检；PyPI 慢时自动换清华镜像）
2. 之后照常运行 `python scripts/mkt.py ...`，脚本发现 `.venv` 会自动改用它
3. 卸载：删除 `.venv` 文件夹即可

不跑 setup 也能用：A股行情、指数、板块、资金流、涨停池、K线、研报库、财联社电报、海外行情（Yahoo 直连）、底稿、lint 都只用标准库。缺的只有交易日历、个股新闻、宏观日历（需 akshare）；没有交易日历时，交易日改用上证指数K线推断。

`.venv` 绑定本机和本机 Python 版本：换电脑、分享给别人时不要带 `.venv`，对方重新双击 `setup.bat`。

```bash
python scripts/mkt.py selftest     # 逐个检查数据源，失败的源不要用
```

在 Codex 里运行需要允许命令联网（沙盒默认可能禁止）。

所有命令加 `--json` 输出 JSON。取数类命令的结果默认落盘到当前目录的 `fha-runs/日期/时分秒-命令.json`（`--no-save` 关闭，`--out` 改目录），事实底稿的“来源”列写这个文件名。

## 1. 命令速查（按四步流程）

| 步骤 | 命令 | 给你什么 |
|---|---|---|
| 第一步 开场 | `now` | 日期、星期、今天是否交易日（含节假日）、最近交易日、A股时段、是否走海外复盘（`route_global`）、开场白原句 |
| 第一步 列表 | `scan` | 指数、两市成交（两种口径）、涨跌家数、行业/概念板块两端、行业资金流两端、涨停/跌停/炸板、连板梯队、涨停行业聚集；`must_cover` 列出必须进列表的方向（创业板或科创50跌超2%、指数与涨跌家数背离、休市日）；v7.5 起同时给出 `global`（海外与亚太）、`us_watch`（美股关键个股，按存储、算力芯片、光通信与数据中心、光伏与清洁能源、中概互联分组，带组平均涨跌）和 `gaps`（没取到的数据清单） |

| 第三步 情绪 | `limit --date 20261030` | 涨停数、跌停数、炸板数、封板率、连板梯队、涨停行业分布、首次封板时间、封单金额；盘中查询会提示收盘后重拉 |
| 第三步 历史 | `kline 300308 --days 30` | 日K线（东财为主，腾讯备用）、区间涨跌、涨停日期（按该股的涨跌停幅度判断） |

| 第三步 新闻 | `news stock 300308` | 东财个股新闻（最近约10条） |

| 第四步 检查 | `lint draft.md --ledger ledger.md` | 网址、证券代码、图片占位符、硬禁用表达、编辑残留、排版装饰、过精确的涨跌幅、“X月X日（周X）”星期错误、节尾总结句、底稿里找不到的数字；v7.5 起加：底稿里没有链接或落盘文件的机构观点（error）、其他没有链接的行（warn）、正文提到但底稿里没有的机构（error） |
| 第四步 比对 | `lint final.md --ledger ledger.md --before draft.md` | 以上全部，加润色前后的数字和限定词变化、确定性/状态词变化、引述主体增减；终稿与初稿完全相同时 warn |

### 2.1 速度与坏源记忆（v7.4.1）

- `scan`、`recap`、`selftest`、`global`、`quote` 内部并发取数，结果里的 `elapsed_s` 是耗时
- 某个主机超时或返回 403/429 后，记入 `.cache/source_health.json`，10分钟内所有命令直接跳过它，不再重复等超时；对方偶尔断开连接不记
- `selftest` 无视记忆重新检测并刷新；环境变量 `FHA_NO_HEALTH=1` 可关闭这个机制
- 默认超时6秒、只重试1次；超时和 403/429 不重试，东财按主机轮换代替重试

## 3. 用法要点

### 3.1 行情

- 收盘稿只用 `basis` 为“收盘”的数据；“盘中”只能写成“截至XX时”；“旧数据”不得写入
- 正文用 `write_as` 字段的写法即可；核心事件数字（订单、利润、入股金额）另从公告取精确值
- `limit` 字段已按板块区分涨跌停幅度，“20CM涨停”可直接用
- 搜索网页只用于消息背景，不作为涨跌幅来源

### 3.2 热点列表（第一步）

`scan` 的输出直接对应 SKILL.md 第3节的扫描顺序。第一步只用它快速瞄准题目，不深挖。重点看：

1. `index.breadth`：指数涨但下跌家数远多于上涨家数，就是“指数与个股背离”
2. `industry.bottom` / `concept.bottom`：领跌方向
3. `industry_flow.bottom`：主力净流出最多的方向，常是高位兑现
4. `limit.seal_rate_pct`、`limit.ladder`：情绪强弱、空间龙头
5. `limit.top_industries`：涨停聚集的行业，常是当日主线
6. `must_cover`：必须进列表的方向
7. `industry_flow.top` 与 `industry.top` 对照：资金流入第一但涨幅不靠前、或和海外同产业链走势相反的方向，常是盘面解读里“对不上的数据”
8. `us_watch.groups`：隔夜美股哪条产业链涨、哪条跌，A股同链条是否同向
9. `gaps`：照抄进热点列表的“数据缺口”，补一句对文章的影响

### 3.3 解释涨跌时的数据链

SKILL.md 1.6 要求的“仓位 → 触发 → 踩踏”链条，可以这样取数：

- 拥挤度：`kline` 看区间涨幅和换手；ETF 份额变化用搜索
- 资金：`flow` 看板块主力净流入/流出
- 触发：`news cls` 找当天的消息，核对发布时间
- 结果：`limit` 看跌停和炸板

### 3.4 券商观点核验

写进正文的每一条券商观点，都先跑一次：

```bash
python scripts/mkt.py reports --org 华泰 --kw 铜 --days 30
```

- 能检索到：打开 `page` 或 `pdf` 核对要引用的那句观点确实在原文里，再用返回的日期写“X月X日发布的研报”，超过一周的写“此前”“近期”；机构、标题、日期记进底稿
- 检索不到：先看 `coverage`。不完整时缩短 `--days`、加 `--org` 或加大 `--max-pages` 再查；覆盖完整仍然没有，就不得引用，改用公告、专家采访等替代信源
- 外资投行观点东财研报库没有，只能通过 Reuters、Bloomberg 等报道核实，并注明转述来源

### 3.5 宏观数据

引用任何 CPI、PPI、PMI、非农等数字之前：

```bash
python scripts/mkt.py calendar --date 20261015
```

状态为“未公布”的只能写“市场预期”。海外数据以官方日历（BLS、BEA、统计局）为最终依据。

### 3.6 海外与商品

- Yahoo 不通时 `global` 依次改用东财、新浪，`source` 写 `sina 代码` 或 `eastmoney 代码 名称`，`fallback_errors` 记下前面源的错误，`sources_down` 列出本次判定不可用的源，`elapsed_s` 是总耗时
- 全部源都取不到时结果带 `error`，部分品种取不到时带 `missing`：这些品种用搜索补，底稿注明来源
- 东财口径：代码见 `EM_GLOBAL`（如 100.SPX、101.GC00Y），返回名称和预期不符就不采用；美股指数按美东时间判断收盘，其他品种标“未判断是否收盘”；期货涨跌幅相对昨收
- 换了运行环境先跑 `python scripts/diag.py`：逐个测各数据源的连通、耗时和返回内容，输出贴给维护人判断
- 新浪口径：美股 `basis` 按美东时间判断收盘（16:00 后为收盘）；期货是最新成交价、涨跌幅相对前结算价，不是收盘价；铜 `hf_HG` 单位是美分/磅；日经、富时、DAX 的 `basis` 标“未判断是否收盘”，写之前看 `bar_date`
- 新浪的 `int_dji`、`int_nasdaq`、`int_sp500` 是过期数据，不要用

- `global` 的 `bar_date` 是最后一根日线的日期，写“隔夜”前确认它是前一个美股交易日
- 周末、假日的期货报价不是正式收盘价，正文必须注明
- 历史极值（“一度涨至XXX美元”）必须再找一个独立来源确认，脚本只给最近10天
- 10年期美债直接用 `^TNX`（单位是%）；2年期美债请用搜索核对

## 4. 已知限制

- 全部是网站的公开接口，不是官方 API，网站改版可能失效。失效时先跑 `selftest` 定位，再 `pip install -U akshare` 或改用搜索
- 节假日识别依赖新浪交易日历（需 akshare）；没有日历时用K线推断，盘前无法确认当天是否交易日，`now` 会标出
- 财联社电报翻页、成交额和涨跌家数的口径，首次使用时各拿一天的财联社收评核对一次
- 东财接口高频调用可能被临时限流，`scan` 一次约10个请求，正常使用没有问题
- `recap` 的保护：三大指数任一取不到时不出草稿、不写底稿（`draft_blocked` 说明原因）；涨停池取不到时草稿不写涨停数（不会写成“0只”）；板块涨跌个数与板块排行来源或层级不同时，草稿不写“多数收涨/收跌”，`warnings` 里会说明
- 涨停池的行业字段 `hybk` 是东财二级行业名，超过4个字会被截断（如“汽车零部”“自动化设”），写入正文前补全
- 微信公众号文章有验证拦截，需用户手动粘贴正文
- 外资研报、彭博终端数据没有免费来源，只能用权威媒体报道转述
