# 地缘事件 × 大宗商品跨资产分析工作流

## 适用场景

当文章核心驱动是地缘政治事件（海峡危机、战争冲突、制裁博弈等），且需要展开大宗商品（黄金、原油、铜等）价格影响分析时，使用本工作流。

## 三步研究法

### 第一步：事件还原（多语言交叉搜索）

地缘事件的中英文报道往往存在视角差异和信息不对称，必须两边都搜。

```yaml
英文搜索：
  query: "Strait of Hormuz Iran latest news June 2026"
  源: mcp_vibe_trading_web_search
  目的: 获取一手军事/外交动态（AP、BBC、CNN、Guardian）

中文搜索：
  query: "霍尔木兹海峡 最新消息 2026年6月"
  源: mcp_vibe_trading_web_search
  目的: 获取中方表态、A股影响、中文财经解读

深度阅读：
  对关键文章用 mcp_vibe_trading_read_url 获取全文
  优先顺序: AP/BBC > Guardian/CNN/CNBC > 新华网 > Mitrade/金十
```

**关键技巧**：同一天用中英文各搜一次，把事件时间线拼完整。英文侧重军事/谈判细节，中文侧重市场解读和区域影响。

### 第二步：商品价格数据提取

**绝对不要用 web_search 查商品价格**（混入历史新闻）。统一用 yfinance 获取精确 OHLCV。

```yaml
原油：
  代码: "CL=F" (WTI), "BZ=F" (布伦特)
  源: mcp_vibe_trading_get_market_data(source=yfinance)
  写入格式: "WTI 6月24日报收70.34美元，跌3.92%，3月初以来首次失守70关口"

黄金：
  代码: "GC=F" (COMEX黄金期货)
  源: mcp_vibe_trading_get_market_data(source=yfinance)
  写入格式: "现货黄金跌2.86%收于3999.08美元，七个月来首次收在4000美元以下"
  注意: yfinance 返回期货价格，现货金价需另外核实（如已阅读的文章中提到的数据）

其他商品：
  铜: "HG=F" (COMEX铜)
  白银: "SI=F" (COMEX银)
```

### 第三步：三节叙事结构

地缘事件+双商品的推荐结构：

```
01 事件时间线——冲突侧+外交侧交错展开
   · 军事动作：谁打了谁、什么时间、什么武器、伤亡/损失数字
   · 外交动作：谈判进展、备忘录内容、各方表态
   · 人文细节：滞留船只数量、排雷进展、绕行路线冲突
   · 注意：时间线按最早→最新递进，不混序

02 原油市场——供给面+地缘溢价出清
   · 价格数据：WTI + 布伦特的精确OHLCV（yfinance）
   · 供给图景：豁免许可、港口出口恢复数据、海峡通航量
   · 各方利益：只引用已有报道或机构的分析，不自行归纳
   · 利空侧面：有报道或机构提到停火破裂风险时，按其原话引用

03 黄金市场——美元vs地缘的双线拉锯
   · 价格数据：金价+银价（yfinance）+ 美元指数
   · 宏观面：美联储政策路径、加息概率、PCE数据
   · 机构观点：有真实研报引研报，没有则用分析师在财经媒体的评论
   · 核心矛盾：地缘风险(利多) vs 强势美元(利空)
```

## 常见陷阱

### 1. 时间线混序
多个来源的日期可能不同（时区差异），必须按自己核验的时间轴重排。同一天的事件先军事后外交。

### 2. 商品价格混用
新闻文章中的价格数字经常是前一天的、甚至是几周前的。**每个价格数字必须用 `get_market_data` 重新拉取确认**。特别警惕搜狐等缓存页面。

### 3. "事件→利多黄金"的机械归因
地缘事件不一定推高金价——如果同时美元走强（如美元指数破101、加息概率飙升），金价可能无视地缘风险继续下跌。**不要用LLM推理替代搜索验证**，必须找到真实的价格变动原因。

### 4. 忽略利空逻辑链
对持续数月的热门赛道，不能只搜利多，必须主动搜利空：
- 豁免许可对供给的影响
- 通行量恢复速度
- 需求端压力（如关税、AI投资放缓）
- 搜不到利空就只写盘面数据，不做因果解释

### 5. 引用模糊来源
写具体机构+姓名+日期。报道原文引的是匿名人士时，写成“据{媒体}报道，有分析人士认为……”，媒体名不能省（SKILL.md 1.7）：
- ✅ "德意志银行分析师Michael Hsueh在6月25日发布的报告中…"
- ❌ "分析人士指出…"

### 6. 冲突报道中的"claim vs fact"陷阱
报道军事冲突时，**必须区分"伊朗声称"和"美方声称"和"独立核实"**，不能把单方说法当事实写。

| 错误写法 | 正确写法 |
|---------|---------|
| "伊朗摧毁了8处美军设施" | "伊朗方面声称打击并摧毁了8处美军设施" |
| "美军打击了10个目标"（如果Reuters未确认这个数字） | "美军打击了伊朗的导弹和无人机储存设施及雷达目标" |
| "172艘船在48小时内穿过海峡"（如果实际是6月18日以来） | "据Kpler统计，6月18日以来至少172艘船通过海峡" |

**核查原则**：
- 攻击效果数字 → 优先用美方/第三方（Reuters、AP）确认的表述，伊朗单方数字要标注"伊朗方面称"
- 事件时间承诺 → 引用具体机构的数据口径（"Kpler统计""S&P Global数据显示"）
- 谈判/协议内容 → 引用公开报道和披露文本（"Al Jazeera报道称""TIME披露文本显示"）

## 三节结构的变体：拉锯框架（tug-of-war framing）

当商品市场同时面临两股方向相反的力量时，用拉锯框架替代三节的独立叙事，让读者理解"为什么冲突升级了油和金也未必单边暴涨"。

### 原油的拉锯

```
力 A（利空油价）：通航恢复 → 供给改善 → 地缘溢价出清
  → 数据支撑：豁免许可、阿联酋出口恢复至战前85%、单日78艘通行
力 B（利多油价）：袭船事件 → 安全等级上调 → 战争风险溢价重新计入
  → 数据支撑：油轮被击中、UKMTO威胁等级上调至"较高"、航运保险成本上升
最终写法：两股力量同时呈现，不做方向预测
```

### 黄金的拉锯

```
力 A（利多金价）：地缘冲突升级 → 避险需求
  → 数据支撑：霍尔木兹交火、特朗普强硬表态、科威特巴林遭袭
力 B（利空金价）：美元走强 + 利率维持高位 → 黄金持有成本上升
  → 数据支撑：美元指数破101、核心PCE 3.4%、Fed维持谨慎
结论写法："地缘风险(利多) vs 强势美元(利空)之间的拉锯"
```

### 拉锯框架的结尾

拉锯框架以事实收尾：写清两股力量各自最新的可核实数据（如海峡单日通行船只数、美元指数、核心PCE），不替读者下判断，不用“真正要盯的不是……而是……”这类句式（SKILL.md 11.3第5条）。如果有机构或媒体明确提出了观察指标，可以按其原话引用。

## 事实核查清单（提交前逐项核对）

这条清单来自2026-06-28 session中用户逐条指出的数据错误，建议每次涉及以下数据时专项核查：

| 数据类型 | 核查源 | 常见错误 |
|---------|--------|---------|
| 原油价格（WTI/布伦特） | Yahoo Finance via get_market_data | 价格日期错位（拿了上周数据） |
| 黄金价格 | Yahoo Finance / 交叉比对 | 期货价vs现货价混用、收盘价不可靠 |
| PCE/通胀数据 | BEA官方发布 | 把PCE误写为核心PCE（核心PCE不含食品能源） |
| 加息概率 | CME FedWatch直接数据 | 从新闻文章复制过期概率 |
| 军事打击目标数 | Reuters/AP一手报道 | 引用未经确认的精确数字 |
| 通行量数据 | S&P Global / Kpler / 劳氏日报 | 日期误差（报告日vs数据日） |
| 伊朗/美方声明 | 标注声明主体 | 把单方宣称写成确认事实 |
| 时间窗口 | 每个数字附带具体日期 | 48小时vs自6月18日以来

7. 按 SKILL.md 第11节和13.10去AI味、跑 lint 后交付
